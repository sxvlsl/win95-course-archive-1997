    TITLE  :  Accessing a ReportSmith report via a dBASE DDELINK




OVERVIEW
 
ReportSmith supports DDE links to other Windows applications that
have DDE capabilities.  The following Technical Information
article provides an example of how to call a previously created
ReportSmith report from a dBASE program or from an object on a
dBASE form using the DDELINK class in dBASE and the LoadReport
macro command in ReportSmith.
 
DESCRIPTION
 
dBASE code that communicates with ReportSmith via a DDELINK
object can be run either as a procedure of a normal dBASE program
or attached to a form object.  For example, an OnClick event for
a Pushbutton on a form can include the following code or can
simply call a procedure with the DO <proc name> command.
 
EXAMPLE 1
 
To load a ReportSmith report from a dBASE program and view the
report on screen, integrate the following code into your program.
 
  LOCAL MyRpt
  MyRpt = NEW DDELINK()
  IF MyRpt.Initiate('RptSmith','command')
    ? "Connection to RptSmith initiated"
  ELSE
    ? "Connection to RptSmith failed"
  ENDIF
  MyRpt.Execute('LoadReport "C:\RPTSMITH\VIDEO\Column.RPT","" ')
  MyRpt.Release()
 
EXPLANATION

Initiate property initiates communication with ReportSmith and
specifies that a ReportSmith (macro language)command will be sent
to ReportSmith. If a session in ReportSmith is not already

PATH for the string "RPTSMITH" and try to start a ReportSmith
session. If ReportSmith is not in the DOS PATH, the connection
will fail. The IF/ELSE/ENDIF sequence merely offers Command
window feedback that a connection has been successfully
initiated.  The Execute property of the DDELINK object is then
used to send instructions to the server in it's own language. 
LoadReport is a ReportSmith macro command that expects two
parameters: the name of the report to be loaded followed by
report variables, if desired.  Note the very specific quote
syntax, i.e. outer single quotes and inner double quotes.  Note
also that if you are sending no report variables, "" for the
second argument are required.   
 
Depending on your window placement and size, the ReportSmith icon
may not be visible after the report is loaded.  If the report
icon is not visible, the Windows Alt-Tab keys will shift focus to
the ReportSmith window and your report will be displayed.
 
EXAMPLE 2
 
To print all pages of a report to the default printer queue and
close ReportSmith after the printing operation is complete, use
the following program code:
 
  LOCAL MyRpt
  MyRpt = NEW DDELINK()
  MyRpt.Initiate('RptSmith','command')
  MyRpt.Execute('LoadReport "C:\RPTSMITH\VIDEO\Address.RPT",;
    "@LastName=<Jones>" ')
  MyRpt.Execute('PrintReport 0,0,"","","" ')
  MyRpt.Execute('CloseReport 0')
  MyRpt.Execute('CloseRS 0')
  MyRpt.Terminate()
  MyRpt.Release()

This example adds a (ReportSmith) report variable to the
LoadReport command.  The @ syntax denotes the report variable
name followed by the report variable value delimited by < >. The
semicolon merely signals a dBASE command continuation to the next
line.  PrintReport arguments 0,0 print all pages and null stings
direct output to the default printer queue.  CloseReport and
CloseRS are ReportSmith macro commands that close the previously
opened report and ReportSmith, returning control to dBASE.  The
DDELINK properties Terminate() and Release() terminate the
connection with ReportSmith and release the DDELINK object MyRpt
from memory.
 
EXAMPLE 3
 
To print the first page only of a report to the network printer
named "Jammer" via LPT3 (network connection) using the default
printer driver, change the MyRpt.Execute(PrintReport........)
command line (above) to read as follows:
 
  MyRpt.Execute('PrintReport 1,1,"Jammer","LPT3","" ')
